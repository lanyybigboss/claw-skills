# hv-analysis — 横纵分析法

> **Deep research skill that produces comprehensive PDF reports**

## 核心概念

**横纵分析法**是一个系统性的研究框架，用于深度理解任何研究对象（产品、公司、概念、技术、人物）。它同时运行两条分析线：

1. **纵向（时间深度）** — 从诞生到当下，像讲故事一样完整呈现演变轨迹
2. **横向（同期广度）** — 把同期所有主要竞品/替代方案摆出来逐一对比

两条线交汇时，能看出一些只看现状或只看历史看不出来的东西：
- 为什么它在某个时间点采取了某个关键决策？
- 当时还有哪些选择？为什么没选？
- 现在的竞争格局是如何一步步形成的？
- 未来可能的演化路径有哪些？

**最终产出**：一份 **10,000–30,000 字**的 PDF 研究报告，排版精美，结构清晰。

## 什么时候用这个技能

### 适合的场景 ✅

1. **竞品调研** — 想了解一个新产品的所有主要竞争对手
2. **公司研究** — 深度了解一家公司（融资、产品、团队、文化）
3. **概念探索** — 搞懂一个技术概念（如 RAG、向量数据库、Serverless）
4. **行业分析** — 了解一个新兴行业的发展现状与趋势
5. **写作准备** — 写长文前需要系统性的素材准备
6. **投资决策** — 做投资前尽调（个人或职业）

### 不适合的场景 ❌

1. **查名词解释** — "什么是 Docker？" 用普通对话就行
2. **简单对比** — "A 和 B 哪个好？" 用普通对比对话
3. **实时信息** — "今天股市怎么样？" 用普通搜索
4. **写公众号文章** — 那个用 `khazix-writer` skill

## 研究框架

### 第一阶段：定义研究范围（Scoping）

**必须先做这一步**，否则会陷入信息海洋。

1. **明确研究对象**：
   - 是产品、公司、概念、技术还是人物？
   - 中文名、英文名、别名、常见误解名都要列出来

2. **设定时间窗口**：
   - 起始点：通常是"诞生"或"首次公开出现"
   - 结束点：通常是"当下"或特定截止日期

3. **确定分析维度**（按研究对象类型选择）：

   **产品类**：
   - 目标用户、核心价值主张、关键功能
   - 定价策略、商业模式、用户获取
   - 技术架构、数据来源、合作伙伴

   **公司类**：
   - 创始团队背景、融资历史、组织文化
   - 产品线、收入模型、市场份额
   - 竞争优势、风险因素、未来规划

   **概念/技术类**：
   - 定义与范畴、核心原理、典型应用
   - 发展历史、关键里程碑、学术基础
   - 实现方式、优缺点、学习曲线

4. **设定输出目标**：
   - 报告长度（通常 15-30 页）
   - 重点倾向（偏技术、偏商业、偏使用）
   - 交付时间（允许的研究时间）

### 第二阶段：信息收集（双线并行）

**纵向线（时间深度）**：
1. **起源故事** — 谁、为什么、在什么背景下创建的？
2. **关键里程碑** — 按时间线排列的重大事件
3. **转折点** — 重要战略调整、危机、突破
4. **版本演化** — 主要版本的功能演进
5. **文化/定位变化** — 品牌、口号、目标用户的变化

**横向线（同期广度）**：
1. **直接竞品** — 功能高度重叠的产品
2. **间接竞品** — 解决同一问题的不同方案
3. **替代方案** — 用户可能选择的完全不同路径
4. **生态系统** — 上下游、合作伙伴、衍生品
5. **用户对比** — 不同产品吸引的不同用户群

**信息源优先级**：
1. **官方渠道** — 官网、文档、博客、财报
2. **第三方报道** — 科技媒体、行业分析
3. **用户反馈** — 评测、论坛、社交媒体
4. **数据平台** — SimilarWeb、Crunchbase、GitHub
5. **学术文献** — 论文、专利、技术报告

### 第三阶段：交叉分析（Matrix Analysis）

这是核心分析步骤。创建一个 **时间×维度** 矩阵：

| 时间点 | 纵向事件（自身发展） | 横向环境（同期竞品） | 交叉洞见 |
|--------|----------------------|----------------------|----------|
| 2015 | 产品 V1 发布 | A 产品已占 60% 份额 | 选择差异化切入蓝海 |
| 2017 | 增加企业功能 | B 公司获得大额融资 | 回应竞争压力 |
| 2019 | 开源核心组件 | 行业出现标准之争 | 通过开源建立生态 |
| 2022 | 被大公司收购 | 监管政策收紧 | 寻求资本庇护 |

**关键分析问题**：
1. **为什么在这个时间点做了这个决策？**
2. **当时有哪些替代选项？为什么没选？**
3. **这个决策如何影响了后续发展？**
4. **如果当时选了另一条路，现在会怎样？**

### 第四阶段：报告撰写（PDF 输出）

**报告结构模板**：

```
封面
- 标题：关于 [研究对象] 的横纵分析报告
- 副标题：时间深度 × 竞争广度的系统性研究
- 日期、页数、保密等级

摘要（1 页）
- 研究目的、方法、关键发现
- 适合读者、使用建议

目录

第一部分：研究概况（2-3 页）
- 研究对象定义
- 研究范围与限制
- 分析方法说明

第二部分：纵向分析 - 时间演变（5-8 页）
- 起源故事
- 关键里程碑时间线
- 重大转折点分析
- 版本功能演进图

第三部分：横向分析 - 竞争格局（5-8 页）
- 竞争地图（直接、间接、替代）
- 功能对比矩阵
- 市场份额演变
- 用户群体差异

第四部分：交叉洞见（3-5 页）
- 关键决策分析
- 路径依赖与锁定效应
- 未来演化可能性

第五部分：附录
- 数据来源列表
- 术语解释
- 扩展阅读建议
```

**排版要求**：
- 使用专业字体（思源宋体/黑体、Inter、Roboto）
- 统一配色方案（主色、辅色、强调色）
- 清晰的图表（时间线、对比矩阵、架构图）
- 合理的页边距与行距
- 页眉页脚（标题、页码、日期）

### 第五阶段：质量检查（QC）

**完整性检查**：
- [ ] 时间线没有明显断档
- [ ] 主要竞品都已覆盖
- [ ] 关键决策都有分析
- [ ] 数据来源都已标注

**准确性检查**：
- [ ] 日期、数字、名称都正确
- [ ] 引用都有原始链接
- [ ] 没有明显矛盾信息
- [ ] 专业术语使用正确

**可读性检查**：
- [ ] 结构清晰，逻辑连贯
- [ ] 图表与文字配合良好
- [ ] 语言平实，避免 jargon
- [ ] 重点突出，结论明确

## 执行流程（逐步指南）

### 第一步：接收任务并确认范围
- 明确用户的研究对象
- 确认研究重点（偏技术/商业/使用）
- 设定合理的时间预期

### 第二步：初步调研（30 分钟）
- 快速收集基本信息
- 确认关键时间节点
- 列出主要竞品清单

### 第三步：深度收集（按需 1-3 小时）
- 按时间线收集详细事件
- 按竞品收集对比数据
- 保存所有原始链接

### 第四步：矩阵分析（45 分钟）
- 创建时间×事件表格
- 填写竞品对比数据
- 撰写交叉分析洞见

### 第五步：报告撰写（1-2 小时）
- 按模板结构写作
- 插入图表与数据
- 注意排版美观性

### 第六步：生成 PDF（15 分钟）
- 使用 Markdown → PDF 工具
- 检查格式与链接
- 添加封面与页眉

### 第七步：交付与说明（10 分钟）
- 提供 PDF 下载链接
- 简述关键发现
- 回答用户后续问题

## 常见问题与对策

### 信息过载怎么办？
- **先限范围**：明确时间窗口与竞品数量上限
- **分层处理**：先抓主干，再补细节
- **及时收拢**：每收集 30 分钟就整理一次

### 信息矛盾怎么办？
- **追源头**：找到原始出处
- **看时效**：以最新权威信息为准
- **标存疑**：在报告中注明信息矛盾点

### 数据缺失怎么办？
- **合理估算**：基于已有数据进行合理推断
- **明确标注**：在报告中注明数据缺失与估算方法
- **提供范围**：给出可能的数据区间而非精确值

### 时间不够怎么办？
- **压缩范围**：减少时间跨度或竞品数量
- **聚焦重点**：只分析最关键的时间节点与竞品
- **分段交付**：先交核心部分，后续补充
